Electronic Signatures for Life Sciences

Append-only signature evidence for Odoo 19 Community

Designed to support an organisation's implementation of FDA 21 CFR Part 11 Subpart B and Subpart C.
No compliance with, or certification against, any regulatory framework is claimed. Compliance depends on your procedures, your computer system validation, your training and your monitoring.

Evidence that cannot be rewritten

A signature is an append-only row. It cannot be modified or deleted through the ORM, by any security group, or by direct SQL: a PostgreSQL trigger refuses UPDATE and DELETE on the table. Even a superuser who disables the trigger is detected, because each entry is chained to its predecessor with a SHA-256 digest.

Bound to what was actually signed

Each signature stores a canonical serialisation of the exact content it attests to, together with its digest. Edit the record afterwards and the signature is marked superseded and stops satisfying any requirement — so nobody obtains an approval and then quietly changes the figures.

Two components, every time

Signing requires the identification code and the password. Signing under somebody else's code is refused, recorded, and reported to your security unit within seconds. Repeated failures lock the code out.

Signatures where your procedures need them

Configure which state transition requires which meaning, how many signatures, by which roles, and whether two different people are needed. The transition is refused until they are present and still current.

Small on purpose

Depends only on base and mail. No Enterprise code. No external Python package. No HTTP controller. No custom JavaScript — every control it enforces is enforced on the server, which is the only place worth enforcing it, and every line of front-end code would have to be re-qualified at each upgrade.
