# 05 — Architecture Review

Phase 5 deliverable. Status: **PASS**, after correction of the two defects in
section 3.

## 1. Review against the Odoo architecture

| Point | Verdict | Evidence |
|---|---|---|
| Odoo core is not modified | PASS | No `_inherit` on a core model; no monkey patching |
| Standard module layout | PASS | `models`, `views`, `security`, `data`, `demo`, `report`, `wizards`, `tests`, `static/description` |
| Load order in the manifest | PASS | Security before access lists, data before views, common templates before report actions, menus last |
| Business logic in the models | PASS | Views declare no logic; wizards delegate to model methods |
| No Enterprise dependency | PASS | Dependencies limited to `base`, `mail`, `hr` |
| Odoo 19 syntax | PASS | `models.Constraint`, `<list>`, `<chatter/>`, direct expressions in `invisible` and `readonly` |

## 2. Review against design principles

| Principle | Application |
|---|---|
| Single responsibility | Lifecycle in the document mixin; parameter access in a second mixin; content in each concrete model |
| Open for extension | `_ls_qms_content_fields`, `_ls_qms_revision_defaults`, `_ls_qms_signature_hook`, `_ls_qms_check_group` are overridable |
| Liskov substitution | Every concrete document accepts the whole lifecycle API of the mixin |
| Interface segregation | The parameter mixin is inherited by models that need parameters, including models outside the document lifecycle |
| Dependency inversion | The mixin refers to concrete models through `LS_QMS_DOCUMENT_MODELS` and skips models absent from the registry |
| Do not repeat yourself | The lifecycle is written once for four models; the report control block is written once for three reports |
| Keep it simple | No inheritance chain deeper than one mixin level; no dynamic model creation |
| Separation of concerns | Security in `security/`, presentation in `views/`, printing in `report/` |

## 3. Defects found during the review and corrected

| Identifier | Defect | Correction |
|---|---|---|
| AR-01 | `previous_revision_id` was declared on the abstract mixin as a `Many2one` targeting that abstract model, which Odoo cannot instantiate | Field moved to each of the four concrete models as a self reference |
| AR-02 | `achievement_rate` was displayed with `widget="percentage"`, which expects a ratio between zero and one, so a rate of 45 would have been displayed as 4500 percent | Widget removed; the field is displayed as a number followed by the percent sign |

## 4. Point identified and accepted

`_cron_document_review_reminder` iterates over the four document models and
issues one search per model. With four models the query count is bounded and
predictable. The alternative, a single union query, would require raw SQL and
would bypass the record rules. The iteration is kept.

## 5. Upgrade safety

| Point | Position |
|---|---|
| Data files | All marked `noupdate="1"` |
| Stored computed fields | `date_next_review` and `date_retention_until` are recomputed by the ORM on upgrade; both remain writable so an operator correction is not lost on the next write of the source fields |
| References and versions | Never regenerated by an upgrade |
| Model names | Fixed for the 19.0 series; a rename would require a migration script |
