# Changelog

All notable changes to `ls_cosmetics`.

## 19.0.1.0.3 — 2026-09-25

Remediation of the independent audit of 2026-09-25 (report AUDIT_REPORT_FINAL_2026-09-25.md; details in REMEDIATION_REPORT_2026-09-25.md at the project root).

- F-32: the post-installation hook writing the removed `ir.cron.numbercall` / `doall` fields is removed.
- F-23: `@api.ondelete` deletion guards. F-29: specific exceptions in the tests.

## [19.0.1.0.2] — 2026-08-06

First release with the test suite actually executed. Result of the run
before these fixes: **103 of 108 tests passing, 5 errors, 0 failures.**

### Fixed

- **Security groups did not imply `base.group_user`.** A user holding only a
  Cosmetics group was not an internal user, so they could not read
  `res.company` or create `mail.message`. Any `create()` on a mail.thread
  model raised AccessError, which made the module unusable for anyone not
  separately granted internal-user access. `group_ls_cosmetics_user` now
  implies `base.group_user`, and the other three groups inherit it through
  the existing chain. Found by live test execution on Odoo 19.

### Changed

- `tests/test_label.py::test_imported_product_requires_country_of_origin` and
  `tests/test_pif.py::test_animal_testing_item_must_be_documented` asserted
  `ValidationError` where the workflow gate correctly raises `UserError`
  first. The assertions were wrong, not the module. Both corrected, and two
  new tests added that write the state directly so the underlying
  constraints are genuinely exercised rather than shadowed by the gate.

## [19.0.1.0.1] — 2026-08-05

### Fixed

- **Search views failed to install on Odoo 19.** All eight search views used
  `<group expand="0" string="Group By">`. Odoo 19's `search_view.rng` rejects
  *every* attribute on a `<group>` inside a `<search>` arch — both `expand`
  and `string`. Replaced with a bare `<group>` in all eight files. Confirmed
  against the schema of a running Odoo 19 server; the Group By menu title is
  generated by the client, so nothing is lost.

### Changed

- `tools/static_check.py` gained a `search-schema` check that rejects any
  attribute on a `<group>` inside a `<search>` arch, and a `--odoo-rng` flag
  that validates every arch against Odoo's own schemas where Odoo is
  importable. Negative controls raised from 13 to 14.
- Recorded in `docs/DEVIATIONS.md` as a known checker limitation: offline
  XML well-formedness is not schema validation.

## [19.0.1.0.0] — 2026-08-05

Initial release for Odoo 19.0 Community Edition.

### Added

- **Ingredient register** (`ls.cosmetic.ingredient`) — INCI identity, CAS/EC
  numbers, nanomaterial and CMR flags, perfume compositions, labelling
  exclusions for impurities and processing aids.
- **Annex register** (`ls.cosmetic.restriction`) — Annexes II–VI with
  mandatory source and consolidation date. Ships empty by design.
- **Versioned formulations** (`ls.cosmetic.formulation` and `.line`) —
  composition totalling 100 % w/w, per-line annex evaluation, segregation of
  duties on approval, immutability after approval, revision by new version.
- **Cosmetic product safety report** (`ls.cosmetic.safety_assessment`) —
  Annex I Part A §1–10 and Part B §1–4, Part B gated on a complete Part A,
  approval bound to the named assessor's user account, review reminders.
- **Claims** (`ls.cosmetic.claim`, `.evidence`) — the six common criteria of
  Commission Regulation (EU) No 655/2013, each with a boolean and a
  justification; evidence records; Article 20(3) declarations.
- **Labelling** (`ls.cosmetic.label`) — the seven Article 19(1) particulars,
  the 30-month durability rule, and an ingredient list generated from the
  approved formulation rather than typed.
- **Product Information File** (`ls.cosmetic.pif`) — the five Article 11(2)
  items and the ten-year retention clock of Article 11(1).
- **Algerian prior authorisation** (`ls.cosmetic.dz_authorization`) — the
  sixteen dossier items, the 45-day decision period and the 1-month compliance
  period, per décret exécutif n° 97-37 as modified by n° 10-114.
- Four security groups via `res.groups.privilege`; 34 ACL lines; 10 global
  multi-company record rules.
- Four QWeb PDF reports; three daily scheduled actions; two wizards.
- Offline static checker with 12 check categories, validated against 13
  injected faults.

### Known limitations

- Tests written but never executed; no coverage measured.
- `flake8` / `pylint-odoo` not run.
- Never installed against a live Odoo 19 server.

See `docs/OUTSTANDING_QUALIFICATION.md`.
